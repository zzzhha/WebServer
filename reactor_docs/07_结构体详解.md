# 结构体详解

## 概述

本文档详细说明 Reactor 模块中定义的所有结构体（struct），包括它们的成员变量、用途和在代码中的使用位置。

## 1. HttpServer 相关结构体

### 1.1 PendingChunk（待处理数据块）

**定义位置**: [HttpServer.h](file:///home/zsy/WebServer/cppBackend/reactor/HttpServer.h) 第39行

**定义**:
```cpp
struct PendingChunk {
  std::string data;                                  // 待处理的数据
  uint64_t enqueue_seq{0};                           // 入队序列号
  std::chrono::steady_clock::time_point enqueue_tp;  // 入队时间点
};
```

**用途**: 
- 在 Phase2 异步架构中，表示一个待处理的 HTTP 请求数据块
- 存储在 `ConnectionWorkContext::queued_chunks` 队列中
- 用于跟踪数据块的入队顺序和处理时间

**成员说明**:
- `data`: 实际的 HTTP 请求数据
- `enqueue_seq`: 入队序列号，用于保证处理顺序
- `enqueue_tp`: 入队时间点，用于计算排队时间

**使用位置**:
- `HttpServer::HandleMessage()`: 创建 PendingChunk 并加入队列
- `HttpServer::HandleMessageInWorker()`: 从队列中取出并处理

### 1.2 ConnectionWorkContext（连接工作上下文）

**定义位置**: [HttpServer.h](file:///home/zsy/WebServer/cppBackend/reactor/HttpServer.h) 第45行

**定义**:
```cpp
struct ConnectionWorkContext {
  std::shared_ptr<HttpFacade> facade;                // 连接级的 HttpFacade
  std::mutex mutex;                                  // 保护成员变量的互斥锁
  std::deque<PendingChunk> queued_chunks;            // 待处理数据块队列
  size_t queued_bytes{0};                            // 待处理字节数（用于背压控制）
  bool worker_running{false};                        // worker 线程是否正在运行
  uint64_t next_enqueue_seq{1};                      // 下一个入队序列号
  uint64_t next_response_seq{1};                     // 下一个响应序列号
  uint64_t last_applied_response_seq{0};             // 最后应用的响应序列号
  std::map<uint64_t, WorkResult> pending_results;    // 待应用的响应结果映射
};
```

**用途**:
- 管理单个连接在 Phase2 异步架构中的完整状态
- 隔离不同连接的处理状态，避免竞争条件
- 支持乱序处理、顺序回写的异步模式

**成员说明**:
- `facade`: 连接级的 HTTP 协议处理对象，每个连接独立实例
- `mutex`: 保护队列和状态变量的线程安全
- `queued_chunks`: 待处理的 HTTP 请求数据块队列
- `queued_bytes`: 连接级待处理字节数，用于背压控制
- `worker_running`: 标记是否有 worker 线程正在处理该连接的数据
- `next_enqueue_seq`: 保证入队顺序的序列号生成器
- `next_response_seq`: 保证响应顺序的序列号生成器
- `last_applied_response_seq`: 记录最后应用的响应序列号
- `pending_results`: 按序列号存储的待回写响应结果

**使用位置**:
- `HttpServer::HandleNewConnection()`: 创建并设置到连接上下文
- `HttpServer::HandleMessage()`: 访问队列并触发 worker
- `HttpServer::HandleMessageInWorker()`: 处理队列中的数据
- `HttpServer::PostResultToIoLoop()`: 存储处理结果

### 1.3 WorkResult（工作结果）

**定义位置**: [HttpServer.h](file:///home/zsy/WebServer/cppBackend/reactor/HttpServer.h) 第57行

**定义**:
```cpp
struct WorkResult {
  uint64_t response_seq{0};                          // 响应序列号
  std::string request_id;                            // 请求ID（调试用）
  std::string method;                                // HTTP方法
  std::string path;                                  // 请求路径
  std::string route_bucket;                          // 路由桶（用于指标统计）
  bool has_response{false};                          // 是否有响应数据
  std::string response_data;                         // 响应数据
  bool close_after_send{false};                      // 发送后是否关闭连接
  bool has_sendfile{false};                          // 是否包含文件发送
  int sendfile_fd{-1};                               // 文件描述符
  off_t sendfile_offset{0};                          // 文件偏移量
  size_t sendfile_length{0};                         // 文件长度
  bool is_error{false};                              // 是否是错误响应
  bool is_download{false};                           // 是否是下载请求
  size_t sendfile_bytes{0};                          // 已发送文件字节数
  long queue_wait_ms{-1};                            // 队列等待时间（毫秒）
  long worker_exec_ms{0};                            // worker执行时间（毫秒）
  long parse_route_ms{0};                            // 解析路由时间（毫秒）
  long business_ms{0};                               // 业务处理时间（毫秒）
  long serialize_ms{0};                              // 序列化时间（毫秒）
  std::chrono::steady_clock::time_point io_enqueue_tp; // IO入队时间点
};
```

**用途**:
- 封装 worker 线程处理 HTTP 请求的完整结果
- 包含响应数据、文件传输信息和性能指标
- 支持乱序处理、顺序回写的异步模式

**成员说明**:
- **序列和标识**: `response_seq`, `request_id`, `method`, `path`, `route_bucket`
- **响应数据**: `has_response`, `response_data`, `close_after_send`
- **文件传输**: `has_sendfile`, `sendfile_fd`, `sendfile_offset`, `sendfile_length`, `is_download`, `sendfile_bytes`
- **错误处理**: `is_error`
- **性能指标**: `queue_wait_ms`, `worker_exec_ms`, `parse_route_ms`, `business_ms`, `serialize_ms`, `io_enqueue_tp`

**使用位置**:
- `HttpServer::ProcessHttpRequest()`: 填充 WorkResult 结构
- `HttpServer::PostResultToIoLoop()`: 传递到 IO 线程
- `HttpServer::ApplyPendingResults()`: 按序应用响应

## 3. Buffer 相关结构体

### 3.1 Block（内存块）

**定义位置**: [Buffer.h](file:///home/zsy/WebServer/cppBackend/reactor/Buffer.h) 第11行

**定义**:
```cpp
struct Block {
  void *data;                                        // 数据指针
  size_t size;                                       // 已使用大小
  size_t capacity;                                   // 总容量

  Block(size_t cap) : capacity(cap), size(0) {
    data = MemoryPool::allocate(cap);                // 使用内存池分配
  }

  ~Block() {
    if (data) {
      MemoryPool::deallocate(data, size);            // 使用内存池释放
    }
  }
};
```

**用途**:
- BufferBlock 内部使用的内存块单元
- 通过内存池分配，提高性能
- 支持分块存储，避免大块内存分配

**成员说明**:
- `data`: 实际的数据存储指针
- `size`: 当前已使用的字节数
- `capacity`: 内存块的总容量

**使用位置**:
- `BufferBlock::append()`: 向块中写入数据
- `BufferBlock::getIOVecs()`: 获取块的 iovec 表示
- `BufferBlock::allocNewBlock()`: 分配新的内存块

## 5. 系统结构体（外部定义）

### 5.1 iovec（IO向量）

**定义**: 系统头文件 `<sys/uio.h>` 中定义
```cpp
struct iovec {
  void  *iov_base;    /* Starting address */
  size_t iov_len;     /* Number of bytes to transfer */
};
```

**用途**:
- 用于 `readv` 和 `writev` 系统调用
- 支持零拷贝的分散/聚集 IO 操作

**在 Reactor 中的使用**:
- `BufferBlock::getIOVecs()`: 将缓冲区数据转换为 iovec 数组
- `Connection::writecallback()`: 使用 `writev` 批量发送数据
- 提高数据发送性能，减少系统调用次数

### 5.2 epoll_event（epoll事件）

**定义**: 系统头文件 `<sys/epoll.h>` 中定义
```cpp
typedef union epoll_data {
  void        *ptr;
  int          fd;
  uint32_t     u32;
  uint64_t     u64;
} epoll_data_t;

struct epoll_event {
  uint32_t     events;      /* Epoll events */
  epoll_data_t data;        /* User data variable */
};
```

**用途**:
- epoll 系统调用的事件结构
- 关联文件描述符和关注的事件

**在 Reactor 中的使用**:
- `Epoll` 类中的 `events_[MaxEvents]` 数组
- `Epoll::updatechannel()`: 设置 `ev.data.ptr = ch`
- `Epoll::loop()`: 从 `events_` 数组中提取 Channel 指针

## 结构体设计特点总结

### 1. 线程安全设计
- `ConnectionWorkContext` 包含互斥锁保护共享数据
- 原子变量用于序列号生成
- 避免竞态条件和数据竞争

### 2. 性能优化
- 使用内存池分配 `Block` 结构
- `iovec` 结构支持零拷贝操作
- 内联小结构体减少内存碎片

### 3. 异步架构支持
- `PendingChunk` 和 `WorkResult` 支持 Phase2 异步处理
- 序列号机制保证乱序处理、顺序回写
- 时间戳字段用于性能分析和监控

### 4. 资源管理
- RAII 模式管理资源生命周期
- 自定义删除器确保正确释放（如 `CtxDeleter`）
- 明确的资源所有权和生命周期

### 5. 监控和诊断
- `RouteMetric` 提供详细的性能指标
- 时间统计字段用于性能分析
- 调试信息字段便于问题定位

## 结构体使用模式

### 1. 作为类内部私有结构体
- 定义在类内部，仅类内可见
- 如：`PendingChunk`, `ConnectionWorkContext`, `WorkResult`, `RouteMetric`
- 优点：封装性好，避免命名冲突

### 2. 作为独立的内联结构体
- 定义在类外部但头文件内
- 如：`SendFileState`, `Block`
- 优点：可被多个类使用，保持简单性

### 3. 作为工具结构体
- 定义在类内部，用于资源管理
- 如：`CtxDeleter`
- 优点：专注单一职责，易于测试

### 4. 系统结构体包装
- 包装系统定义的结构体
- 如：`iovec`, `epoll_event`
- 优点：类型安全，便于C++操作
